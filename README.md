# Дневник смен водителя

Сводка за день и список поездок. Сервер: Node.js + Express 5 + TypeScript, данные хранятся в JSON-файле. Клиент: React 19 + Vite + Tailwind CSS 4.

## Запуск

```bash
npm install
npm run dev        # API на :3001, клиент на http://localhost:5173
npm test           # тесты сервера (Vitest + Supertest)
npm run typecheck
```

Настройки сервера (через переменные окружения):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3001` | порт API |
| `TRIPS_FILE` | `server/data/trips.json` | файл с поездками |
| `TZ_OFFSET_MINUTES` | `300` (+05:00) | пояс водителя |
| `DAY_START_HOUR` | `4` | час начала рабочих суток (см. ниже) |

## Рабочие сутки и ночные смены

День в дневнике — это рабочие сутки с 04:00 до 04:00 следующего дня, а не календарный день. Поездка относится к суткам, в которые она началась. Ночная смена 22:00–03:00 6 октября целиком попадает в 6 октября, вместе с поездками после полуночи. Поездка может закончиться после 04:00, например 03:50–04:20: она всё равно относится к суткам, в которые началась. Час начала суток задаётся переменной `DAY_START_HOUR` (`0` — обычные календарные дни).

## API

`GET /api/days` — дни, в которые были поездки:
`{ tzOffsetMinutes, days: [{ date, trips }] }`

`GET /api/days/:date` — поездки за день (`YYYY-MM-DD`) и сводка:

```json
{
  "date": "2026-10-01",
  "tzOffsetMinutes": 300,
  "summary": {
    "trips": 2, "revenue": 3900, "commission": 585, "net": 3315,
    "cash": { "trips": 1, "amount": 1500 },
    "card": { "trips": 1, "amount": 2400 },
    "busyMinutes": 37,
    "firstStart": "2026-10-01T08:10:00+05:00",
    "lastEnd": "2026-10-01T09:20:00+05:00"
  },
  "trips": [ ... ]
}
```

`POST /api/trips` — добавить поездку. Тело запроса: `{ id?, start, end, amount, payment, commission }`.

| Ответ | Когда |
|---|---|
| `201 { trip, duplicate: false }` | поездка создана |
| `200 { trip, duplicate: true }` | такая поездка уже есть, дубль не создан |
| `400 { error: "validation", issues: [{ field, message }] }` | данные не прошли проверку |
| `409 { error: "conflict", trip }` | этот `id` уже занят другой поездкой |

### Проверка данных

- `amount` — целое число больше 0. `commission` — целое число от 0 до `amount`. Суммы в тенге.
- `start` и `end` — ISO 8601 с указанием пояса, `end` позже `start`, поездка не длиннее 12 часов.
- Поездку из будущего добавить нельзя: `end` не позже текущего момента (допуск 5 минут на расхождение часов).
- `payment` — `cash` или `card`.

### Защита от дублей

1. **По `id`.** Клиент генерирует `id` при открытии формы и сохраняет его до успешного ответа. Если запрос отправлен повторно (двойной клик, повтор после обрыва связи), сервер вернёт уже записанную поездку. Если `id` совпал, а данные другие, сервер ответит 409 и ничего не перезапишет.
2. **По содержимому.** Если `id` нет, сервер сравнивает время начала и окончания (как моменты времени, поэтому `08:10+05:00` и `03:10Z` совпадут), сумму, способ оплаты и комиссию.

Проверка и вставка выполняются синхронно, до записи на диск. Поэтому из нескольких одновременных одинаковых запросов поездку создаёт только один. Файл перезаписывается атомарно: сначала во временный файл, затем `rename`. Записи выполняются строго по очереди.

## Структура

```
server/src/summary.ts     расчёт сводки, определение дня поездки
server/src/validation.ts  схемы zod
server/src/store.ts       хранилище и защита от дублей
server/src/app.ts         маршруты Express
server/test/              тесты сводки, дублей, валидации, API
client/src/components/    переключатель дней, сводка, лента смены, список, форма
```

## Клиент

- Дни переключаются стрелками рядом с датой, клавишами ← и →, лентой дней со сменами или выбором даты по клику на заголовок. Дальше сегодняшнего дня перейти нельзя. Выбранная дата сохраняется в адресе (`?date=`).
- «Лента смены» показывает поездки на шкале часов. Клик по отрезку выделяет поездку в списке.
- Форма новой поездки открывается кнопкой или клавишей N. Комиссия по умолчанию 15% от суммы (как в примере данных), её можно изменить.
